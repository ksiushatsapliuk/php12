# Практична робота 12 — варіант 18

## Мета
Додати до застосунку елемент інтерактивності через CSS-анімацію чи Canvas API - індикатор прогресу, невелику міні-гру чи анімований графік, пов'язаний із реальними даними вашого домену (з практикумів 6, 9, 11), а не декоративний елемент «сам по собі». Для варіанта з Canvas - навчитися будувати цикл анімації через requestAnimationFrame і коректно перемальовувати кадр.

## Що реалізовано
Варіант 18 у PDF — **дошка сусідських оголошень**. За погодженим рішенням до FloraCare додано окрему сторінку announcements.php. Каталог рослин із роботи 08 збережено; між розділами є посилання.

Нове оголошення зберігається в MySQL, з’являється на початку стрічки та отримує CSS-анімацію slide-down + fade-in на 550 мс. Позначка «Нове» плавно згасає за 4 секунди, після чого видаляється. Число карток та їхній вміст беруться з API, без демонстраційних масивів у робочому коді. Старі записи при відкритті сторінки не анімуються. «Оновити стрічку» анімує тільки нові ID, наприклад додані в іншій вкладці.

& C:/php/php.exe -d extension_dir=C:/php/ext -d extension=pdo_mysql -d extension=mbstring -S localhost:8000

## Відповідність крокам PDF
1. Обрано CSS відповідно до варіанта 18.
2. Додано класи announcement-enter/announcement-new і два @keyframes. Анімуються transform та opacity.
3. Canvas не потрібен для CSS-варіанта.
4. render() читає масив announcements, отриманий через GET API або відповідь POST після реального INSERT у БД.
5. requestAnimationFrame/clearRect стосуються Canvas і не потрібні у робочому CSS-модулі.
6. Анімація запускається після успішної публікації; помилковий POST не додає картку. Нові ID з іншої вкладки виявляються при оновленні.
7. Керування — «Опублікувати оголошення» та «Оновити стрічку». Окрема кнопка старт/стоп для короткої одноразової анімації не потрібна.
8. Анімації кінцеві; animationend прибирає клас і позначку. visibilitychange керує animation-play-state, pagehide завершує ефекти. prefers-reduced-motion вимикає рух. DOM старих карток зберігається.
9. Код прокоментовано; локальний коміт має повідомлення `Add animated neighborhood announcements for practical 12`. Перевірка: `git log -1 --oneline`. Відправлення на GitHub не виконується автоматично.

## Безпека і API
GET api.php?resource=announcements — список, найновіші ID першими. POST — створення з title (1–160 символів) і body (1–2000). POST з action=delete та id — видалення. Усі зміни потребують cookie сесії та CSRF (поле csrf або X-CSRF-Token). Немає токена — 403; некоректні поля — 400; видалення через GET — 405. Дані вставляються у DOM через textContent. SQL-входи зв’язуються через prepare/execute. Каталог рослин використовує свій попередній API resource=plants.

## Як перевірити самостійно
1. Відкрити дошку, додати оголошення. Переконатися, що воно перше, плавно з’явилося, позначка згасла й зникла приблизно за 4 секунди.
2. Оновити сторінку: збережений запис залишається без повторної позначки. Додати запис в іншій вкладці, натиснути «Оновити стрічку»: анімується лише новий запис.
3. Перевірити скасування/підтвердження видалення, ввід з клавіатури і вузьке вікно. У налаштуваннях зменшеного руху картка має з’явитися статично.
4. Додати назву `<img src=x onerror=alert(1)>`: вона відображається текстом. Відхилений запит без CSRF не змінює дані. При помилці мережі наявна стрічка зберігається.
5. Запустити повторювані PHP-перевірки з кореня проєкту:
```powershell
& C:/php/php.exe -d extension_dir=C:/php/ext -d extension=curl tools/check_announcements.php --url=http://localhost:8000
& C:/php/php.exe -d extension_dir=C:/php/ext -d extension=curl -d extension=mbstring tools/security_check.php --url=http://localhost:8000
```
Код завершення 0 і failed=0 означають успіх. --output=шлях.json дозволяє зберегти новий протокол. Сценарії створюють власні тестові записи та прибирають їх; запускати на локальній тестовій копії без одночасних сторонніх змін. Візуальні ефекти перевіряються окремо у браузері.

## Виконані перевірки
04.11.2026: PHP 8.5.10, MySQL 8.0.43; окрема тестова база codex_php12_test на порту 3312, сайт на 8120. Робочий config.php залишається на 3307 і practicum12.
- 15 контрольних перевірок API оголошень, 0 помилок.
- 39 перевірок дошки в браузері: дані, обидва ефекти, їх завершення, пауза, зменшений рух, мобільна ширина, мережевий збій, SQLi/XSS/CSRF та видалення; усі пройдені.
- 65 HTTP-перевірок і 23 браузерні перевірки каталогу рослин; усі пройдені.
- Синтаксис: 26 PHP-файлів і 3 JS-файли; помилок немає. Встановлення виконано двічі.

Це кількості контрольних перевірок, не HTTP-запитів або різних атак. Під час анімації за 16 часовими мітками кадрів середній інтервал становив 16.23 мс, максимальний — 62.60 мс. Це локальна перевірка чутливості інтерфейсу, не гарантія постійних 60 FPS. Пауза перевірена викликом visibilitychange з контрольованим document.hidden=true; це не твердження про ручне перемикання вкладок. Старі навантажувальні виміри в results/php08 належать роботі 08.
